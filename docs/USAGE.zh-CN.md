# LOL 连接诊断助手

**延迟看起来正常，却进不了大厅或一直卡在加载？** 这是 Windows 上的 LOL 网络诊断与自有线路分流工具。先记录一次游戏启动，查看卡住的位置、连接错误以及尚未验证的部分，再决定是否需要调整线路。

不懂 IP 也可以先诊断。**作者不提供节点、订阅或代搜服务。** 如果希望省去寻找和维护线路的过程，购买成熟的游戏加速器通常更省事。

## 第一次怎么用

1. 安装 PowerShell 7.2 或更新版本，然后双击 **LolConnect.exe**（原来的 Start.cmd 也可用）。不要双击 `.ps1`，它可能打开记事本。
2. 点击 **开始诊断（不改网络）**。区服不知道可以不填。
3. 像平时一样打开 WeGame / LOL，登录并尝试进入游戏。
4. 卡住时回到工具，选择对应位置，点击 **卡在这里**；正常推进可以点 **已到达这一步**。
5. 点击 **结束诊断，查看结果**。结果会区分观察到的异常、已有进展、可能因素、未检查项和下一步。证据不足时会明确说明，绝不把“没找到错误”当成“全部正常”。

没有代理节点、没有 Clash、没有 Python，也能完成以上流程。首次观察最多十分钟；找不到日志时可通过按钮选择游戏安装文件夹。工具不会替你登录、操作游戏或自动改变网络。自己的标记也是线索，结果不保证自动找到根因。

## 两种地址，不是一回事

- **LOL 目标**：游戏本来要连接的服务器，相当于目的地。工具从本机游戏日志和连接中发现候选项；不确定的保留待确认。可以手动修改域名、IP、端口和分组。
- **代理节点**：你自己准备的中转服务。通常需要协议、地址、端口，有时还需要账号密码；只有一个 IP 并不足以配置代理。

诊断不需要中转服务。只有你希望尝试另一条线路时，才进入 **使用我自己的节点**。工具不搜索、不分发节点。自行准备资料的提示词见 `NODE-RESEARCH-PROMPT.md`。

## 为什么有三组

| 分组 | 对应体验 | 测试能说明什么 |
|---|---|---|
| 大厅与会话 | 大厅、房间、授权、聊天等 | 已确认服务的连接或无认证响应；不等于账号登录成功 |
| 启动配置 | 启动时读取的配置、部分加载过程 | 证书、响应及配置完整下载；不覆盖所有补丁、资源和缓存 |
| 对局连接 | 实际游戏实时数据，主要关注 UDP | 当前仅展示能力声明和观察证据，真正可玩需实际对局验证 |

这是按用途分组，**不是三个固定 IP，也不是按画面依次切换**。每组可能有多个服务，且会同时连接。聊天失败不一定影响对局；测试全通过也不保证游戏能进去。内置 hn10 模板只是历史参考，其他区服、模式和版本必须重新确认目标。没有观察到对局服务器时显示未验证。

各组的问号按钮会在应用里解释这些区别。

## 可选：尝试自己的线路

1. 在诊断的服务明细中确认目标；未知地址不会自动启用分流。
2. 打开自己的节点入口，在设置配置已有 Clash Verge/Mihomo、Python 3.9+ 和测试网卡。Python 仅用于主动探测；Mihomo 用于节点测试与分流，本包不附带它们。
3. 在节点管理中自行添加 HTTP/SOCKS5 节点，或选择本机 Clash 中已有的节点。节点支持搜索、修改、停用和删除。
4. 点击 **一键测试全部**，然后展开三组下拉列表查看已有结果、时间及待复测状态。测试可取消。目标、节点或网络配置改变后需要复测。
5. 选择每组路径，或通过 **单独分配** 为某个服务选择其他路径。保留可用直连；保存方案不会自动应用。
6. 点击 **预览并应用组合**，看清哪些连接会转发后确认。应用需要 Clash 规则模式与 TUN；正在对局时通常不要切换。
7. 重新打开游戏，再运行一次诊断，在证据明细查看实际游戏新连接是否走预期路径。没有进程身份、连接时间或代理链时只会显示证据不足。
8. 撤回请点 **恢复接管前配置**。关闭窗口不会自动撤回分流。若订阅被其他程序修改，工具会阻止旧备份覆盖，可在 Clash 重新加载自己的订阅。

“测试当前网络”可能经过已经运行的 VPN/TUN，不能直接称为直连。测试只访问无认证服务，不重放登录请求；401/404 只按具体目标契约解释。UDP 声明不是实际双向传输证明。不同运营商、地区或时间的结果不能直接套用。

## 节点不完全可信时，这能做什么

按游戏目标分流可以减少交给节点的流量，并省去手写规则，但**不能让不可信节点变安全**。节点仍可能看到连接目的地、时刻和流量特征；地址/端口规则无法区分同一服务里的公开请求和授权请求。测试通过不代表节点可信。工具保持 TLS 证书校验，不要求安装节点方证书。

应用预览会说明转发范围和游戏进程 UDP 补充规则。已有 Clash 的其他规则仍然生效，本工具不保证电脑其余流量都直连。

## 数据和 GitHub 发布

本地数据在 `%LOCALAPPDATA%\LolRouteLab`，包括节点、设置、测试历史、诊断、方案和恢复备份。密码使用 Windows 当前用户 DPAPI 保护。程序不自动上传日志或遥测；诊断保留提取后的连接字段而非日志全文。**导出脱敏摘要**使用字段白名单，不导出节点、原始日志和本机路径。

源码包不包含用户数据、真实节点、私人日志或依赖二进制。不要上传整个工作区或上述用户目录：恢复 YAML 可能包含订阅凭据。`.gitignore` 只是辅助，发布前仍需检查。公开仓库只包含工具源码和已检查的素材。

## 开发验证与限制

PowerShell 7 下运行 `test-lol-lab.ps1`、`test-lol-session.ps1`、`test-lol-routes.ps1`；Python 运行 `python -m unittest discover -p test_lol_probe.py`。隔离核心测试：`pwsh -File test-lol-core-isolated.ps1 -CorePath "你的 mihomo.exe 路径"`，不会开启 TUN 或系统代理。

验证覆盖日志增量读取、错误分类、无节点诊断流程、CRUD、取消、规则生成及独立核心恢复。真实 LOL 游戏流程需用户自行启动验收；不同国服客户端日志格式与受保护进程可能无法完整识别。现有 YAML 合并支持顶层块状列表，不支持全部锚点/内联写法。自动建议只是最新有效结果中的候选，不保证最优路径。

参考：[Mihomo 路由规则](https://wiki.metacubex.one/config/rules/)、[curl 手册](https://curl.se/docs/manpage.html)。

## EXE 启动器

LolConnect.exe 是轻量入口，需要与脚本放在同一个文件夹中；它沿用已安装的 PowerShell 7，不包含完整运行环境。EXE 不改变游戏性能或内存占用。完整解压后使用，不能只分享 EXE。开发者可以运行 Build-Launcher.ps1 从 LolConnectLauncher.cs 重新编译；源码包不附编译结果，Windows 使用包附有 EXE。
